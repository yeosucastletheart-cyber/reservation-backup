# 캐슬디아트 PC 인계

## 소유와 실행 위치

GitHub 소유 계정은 `yeosucastletheart-cyber`입니다. 전용 저장소는 `reservation-backup`,
알림 앱은 `castle-reservation-backup`입니다. 앱은 이 계정의 해당 저장소에만 설치합니다.
개발자의 개인 GitHub 계정이나 PC가 자동 실행의 필수 조건이 되지 않도록 인계합니다.

백업은 GitHub Actions, 감시는 기존 복구 Supabase에서 실행합니다. 캐슬디아트 PC에는
상태 확인 환경을 마련하며 상시 실행 서비스·예약 작업·Docker를 기본 설치하지 않습니다.

## 현장 PC에서 할 일

1. 캐슬디아트 전용 브라우저 프로필에서 GitHub와 Supabase에 담당자가 직접 로그인합니다.
   비밀번호·2단계 인증코드는 채팅이나 공개 문서에 입력하지 않습니다.
2. 저장소 Actions와 실제 생성된 백업 상태 이슈를 즐겨찾기에 등록합니다.
3. 담당자의 GitHub 알림 설정을 확인하고 실제 봇 알림을 수신하는지 확인합니다.
4. 마지막 성공 실행 날짜·사본 날짜, 실패 시 이전 성공본이 유지되는지 확인합니다.
5. PC를 꺼둔 기간에도 정기 실행이 완료되는지 클라우드 기록으로 확인합니다.

수동 복구 점검이 필요하면 해당 PC에 Git·Node.js 22 이상·PostgreSQL 클라이언트를 설치합니다.
자동 백업을 위한 필수 설치가 아니며, 실제 DB 쓰기·migration·복원은 실행 전에 별도 승인을 받습니다.
이 구현의 복구 검증은 별도 읽기 모델의 참조 무결성 검사입니다. 운영 DB 전체 복원이나
Auth·사진·청소·주급 복원 기능으로 안내하지 않습니다.

## 인증정보 인계

- 예약 백업 암호화 키는 기존 성공 사본을 복호화하는 데 필요합니다. 이전을 이유로 새로 만들지 않습니다.
- 현재 개발 PC의 Windows 계정 보호 파일(DPAPI)은 다른 PC에 복사만 해서는 사용할 수 없습니다.
- 전용 비밀 저장소 또는 승인된 암호화 전달 방법을 정한 뒤 새 PC에서 안전하게 다시 등록합니다.
  키·DB 비밀번호·GitHub App private key를 Git, 이슈, 채팅, 일반 문서에 넣지 않습니다.
- 클라우드 환경 Secrets가 등록되면 일상 상태 확인 PC에는 운영 DB 비밀번호나 복호화 키가 필요하지 않습니다.
- 개발자 PC의 접근 해제와 보관 파일 정리는 현장 검증·인계 확인 뒤 승인된 범위에서 수행합니다.

## 인계 완료 기준

- [ ] 캐슬디아트 계정에서 저장소·앱·Secrets와 운영 담당자를 관리할 수 있음
- [ ] 실제 백업 저장·재조회 성공 및 첫 정기 실행 확인
- [ ] 실제 실패/미실행 알림과 정상 복구 알림 수신 확인
- [ ] 기존 사본을 읽는 키 인계와 담당자 복구 절차 확인
- [ ] 현장 PC 로그인·바로가기·관리 안내 확인

현재 현장 PC는 이 대화에 연결되지 않았으며 위 설치·현장 확인을 완료했다고 표시하지 않습니다.
